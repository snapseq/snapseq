A shot waits for the current document to be parsed (`DOMContentLoaded`) before the plugin hooks and the readiness wait, so a shot right after a click that navigates sees the whole new page; a page that never finishes parsing holds it to the navigation timeout, so navigate before the shot, not from a hook. `snapPage` puts the scroll position back after the shot, into the same document only. A page about one screen tall whose content scrolls inside an element, open shadow roots included, is not grown: it is shot at the device's viewport, with a note naming the element, and a shell that grows with the viewport gets the note instead of a refusal. A plain `snap` waits only for the visible images in the viewport (or the `clip`) and above it, one at `opacity: 0` included; a full page still waits for all of them. Image notes name the first image (`N images still loading after 5 s (first: <url>)`, the URL without its credentials, query or hash), a broken image that is shown gets `N images failed to load (first: <url>)`, and the DOM note names the element that changed most. Notes a `beforeSnap` hook pushes to `shot.notes` reach `shots.txt` and the terminal, before the readiness notes, and a `snapPage` refusal lists them. `shot.deviceScaleFactor` comes from the device's option rather than the page, and is `1` from `afterSnap` on for a shot with `scale: "css"`. `--record=0` and `--record=false` replay instead of recording, and `--record` refuses a second URL that would overwrite the same replay file in one device's run. An empty device name is refused, and the reporter drops control and format characters from error text.
