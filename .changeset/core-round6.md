`snapPage` waits for images again after it grows the viewport a second time, so an image that a newly shown section starts loading is in the shot or noted; a slow page can then spend two 5 s image budgets in one `snapPage`. A page whose `html` has `overflow-y: auto` and whose layout follows the viewport is now refused like any other, instead of being noted as scrolling inside `<html>`; a `body` with containment still counts as an inner scroller. `snap` no longer waits for an image that a scrolling panel or another overflow box cuts out of view: the check follows the containing-block chain (a fixed image, or an absolute one whose containing block is outside the box, is not cut) and keeps any image it cannot be sure of. The image wait adds one load and one error listener per image and removes them when it ends. A capture whose directory holds another capture's output, a subdirectory with a `shots.txt` (`home.capture.ts` on `mobile` and `home/mobile.capture.ts` on `desktop`), now fails with `snapseq: refusing to wipe …: it holds another capture's output (…)` and deletes nothing; any other subdirectory, such as one a hook wrote, is wiped as before.
