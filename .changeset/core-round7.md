`--record` treats a `FormData` POST sent twice as one request: a multipart body is compared with its delimiter lines normalized (the boundary is read from the `boundary` parameter of a `multipart/form-data` content type; field values are left alone), so the same form no longer fails as a second request, and the second-request error ends with `(the bodies differ)` when only the body changed. `failed.png` is written when an image in the initial HTML never answers: the teardown abandons pending images before its screenshot, `<picture>` sources and images in frames included (their `src` and `srcset` are removed, in the teardown only, never in a shot); the screenshot used to wait on the same load event and time out. `SNAPSEQ_OPEN=false` keeps the run directory closed like `0`, in any case. A readiness note keeps the `url`, `src` or `image` query parameter of an image served through a loader (`…/_next/image?url=/img/hero.jpg`): decoded, without its own query, hash or credentials (however they are encoded), left out when it is not an http(s) URL, and cut to 60 characters; every other parameter is still dropped. The troubleshooting entry for an image that never answers lists the fixes that work.
